\section{Limitations and threats to validity}
\label{sec:threats}

\paragraph{Harness version drift.}
Harnesses ship weekly.
Each release pins versions and reruns conformance on every bump; results describe the pinned versions only.

\paragraph{Exposure asymmetry.}
Harnesses route the same intent through different tools: Codex has no read, search or list tool and reads files through the shell, so read faults never apply to it.
Success metrics are not normalized for this; the asymmetry is part of what is measured, and per-class exposure is reported for every trial.

\paragraph{Unequal delivery.}
A harness may hide part of a fault from the model, as with Claude Code's fixed success line for writes.
Comparisons use only parity-set types, undelivered faults are rerun and then excluded, and fidelity is reported per board.

\paragraph{Differences inside the fixed axis.}
Harnesses request thinking differently, some send side requests, and fx reaches the model through the Vercel AI Gateway rather than the provider's API.
The fixed axis is therefore close to identical, not identical; each difference is shown next to its row.

\paragraph{Cost sources.}
Each harness reports its own cost: a session total, a sum of per-response costs, or settled gateway records.
These are not provider billing and are not fully cross-checked.

\paragraph{Injector discovery and attribution.}
An agent may find injector files or see a harness note that a hook intervened.
Injector names are neutral, discovery is detected and reported, and attribution is recorded per harness from conformance.

\paragraph{Contamination.}
Every task file the agent does not see carries a canary string so it can be filtered from training data.
