Run from `main` at 574ce7fb, which adds the D-0053 Codex injector and analysis change to the pre-registration tag `pre-m6-2026-11-10` (a listed deviation, D-0052 item 3). ## 1. What ran

17 Track N tasks (the 12 M5 tasks and the 5 batch 1 tasks that passed calibration) x 5 configs x `clean` and `moderate` x 3 attempts = 510 trials, seed `m6-2026-11-10`. The configs are `cc-claude`, `fxh-claude`, `pi-claude`, `opencode-claude` and `codex-claude`.

- Infrastructure failures (no verifier reward, METHODOLOGY 6): 2 of 510 (0.4%). One was an `fxh-claude` provider TLS failure (`n-bisect-regression`, `clean` attempt 0). The other was a `cc-claude` agent setup timeout (`n-transit-boards`, `clean` attempt 1). Each was rerun once and passed.
- Another `fxh-claude` trial (`n-split-reports`, `clean` attempt 1) stopped on the same provider TLS failure. Its verifier still wrote a reward of 0, so under METHODOLOGY 6 it is a scored trial, not an infrastructure failure, and it stays in the evidence as scored. It was also rerun, but that rerun is not part of the evidence (`commands.txt`).
- The first `fxh-claude` job (`clean` attempt 0) stopped when a session with no steps failed ATIF validation in `cmca_harbor/fx.py`. The adapter now returns no trajectory for such a session, and that job was finished with `harbor jobs resume`.
- The shell running attempt 0 hit the session's background time limit, which cut one in-flight trial each of `cc-claude` and `pi-claude` (`moderate` attempt 0). Both jobs were finished with `harbor jobs resume`. The spend of the two cut trials before the cut is in no `result.json`.

## 3. Raw outcomes and delivery

Successes over 51 scored trials per config and profile (17 tasks x 3 attempts). Under `moderate`, a trial whose trajectory shows an applied fault as not delivered is excluded and rerun once (METHODOLOGY 6). The counts here use the rerun in its place.

| Config | `clean` | `moderate` | Faults applied | Verifiable | Delivered | Delivery reruns |
|---|---|---|---|---|---|---|
| `cc-claude` | 50 | 45 | 122 | 91 | 90 | 3 |
| `fxh-claude` | 50 | 46 | 224 | 179 | 179 | 1 |
| `pi-claude` | 48 | 42 | 103 | 75 | 75 | 0 |
| `opencode-claude` | 50 | 43 | 118 | 79 | 79 | 0 |
| `codex-claude` | 47 | 46 | 143 | 103 | 103 | 3 |

Verifiable excludes `trunc`, `drift` and `rate`, which the trajectory cannot confirm. No applied fault was logged as undeliverable, including the D-0053 `outlived-yield` case.

The 7 trials that were rerun:

- **`cc-claude` (3).**
  - In two trials (`n-ledger-fix` attempt 0, `n-csv-export` attempt 1), an `empty` fault hit a command whose output was over about 30 KB. Claude Code saved the full output to a session file and showed the model a `<persisted-output>` block whose 2 KB preview was blank. The injected empty result replaced only the preview. The saved file kept the real output (the 35,639-byte file in the `n-ledger-fix` rerun), and the model can read it.
  - In the third trial (`n-split-reports` attempt 2), an `empty` fault hit a command that exited with code 1. The result kept the `Exit code 1` text.
  - The `n-ledger-fix` rerun hit the same over-30 KB case again, and is the one undelivered fault in the table.
- **`codex-claude` (3).**
  - In two trials (`n-make-build` attempt 2, `n-split-reports` attempt 0), Codex rejected the command (`exec_command failed: CreateProcess ... Rejected`), so it never ran and there was no output to empty.
  - In the third (`n-port-conflict` attempt 1), Codex truncated a 97,834-token output, and the `poison` line was not in the part shown.
- **`fxh-claude` (1).** In `n-split-reports` attempt 1, a `falsefail` fault hit a `write_file` call that fx refused for a missing `content` field.

All 7 reruns delivered every verifiable fault except the `cc-claude` `n-ledger-fix` one above.

## 5. Owner decision

`cc-claude` is below the 99% delivery bar, so the stage goes to the owner (D-0052 item 4). Neither cause is fixed by rerunning, because it repeats on the same calls:

- Claude Code persists outputs over about 30 KB outside the hook's reach.
- An `empty` fault on a command that exits non-zero keeps the exit text, like the M5 finding for shell faults on non-zero exits.

The next step is a plan like D-0053: either fix `injector-claude-code` for persisted outputs, or log those faults as undelivered and declare the gap. Stage 3 should not start before that.
