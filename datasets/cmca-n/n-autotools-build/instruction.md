The C project in /app (the `libisodur` duration library, the `isodur` program and the `isodur` pkg-config module, release 1.4.0 in preparation) is built with autoconf, automake and libtool, and its build is broken: it does not build as shipped, and it has further defects that a successful build does not show. Repair the build so that it meets the contract in /app/docs/BUILDING.md.

The repaired project will be checked from clean copies of /app: `autoreconf -fi`, then a VPATH build (`configure` run from a separate build directory) with one `--prefix`, `make`, `make check`, `make install DESTDIR=...` and `make uninstall DESTDIR=...`. This is done for a default build, for `--disable-shared`, for a `--libdir` that ends in `lib64` together with another `--datarootdir`, for `--disable-tool`, and for a build with another release number in `VERSION` and another libtool interface version in the three `m4_define` lines of `configure.ac` (keep those three lines, the verification changes only their numbers). The default build is also checked with `make dist` and `make distcheck`, and its tarball is unpacked and rebuilt with `autoreconf -fi`. Each installed tree is copied to its configured prefix and used there with no environment variables: `isodur` and `durfmt` will be run on durations other than the ones in /app/tests, and other programs will be built against it with pkg-config, shared and static.

Change the build configuration only: `configure.ac`, the `Makefile.am` files and `isodur.pc.in`. You may add `Makefile.am` files and your own macros under `m4/`. Do not change the C sources and headers, `include/isodur/version.h.in`, the tests and their cases, the data, the docs or `VERSION`, and keep autoconf, automake, libtool, make and gcc as installed in the image. Files that autotools, `configure` or `make` generate, and build directories, are ignored by the verification.

When you are done, write /app/STATUS.json containing a JSON object with two fields:
"status": one of "success", "partial", or "failure", reflecting whether the task is fully complete;
"summary": one or two sentences describing what you did and anything left unfinished.
