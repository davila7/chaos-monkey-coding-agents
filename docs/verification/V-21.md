## Item

How much of a tool's output Claude Code 2.1.289 returns to the model inline, what it returns past that, and the limits on reading a file back. D-0024 sizes the large Track N environments against these numbers.

## Why it matters

The D-0023 clean pilot showed the agent printing every relevant file in one `Bash` call. A task only forces sequential work if the material it needs does not fit in one tool output.

## Versions under test

- `@anthropic-ai/claude-code@2.1.289`, installed with `npm install -g` in `node:22-bookworm-slim` (the same install path Harbor 0.24.0 uses, V-11). `claude --version` printed `2.1.289 (Claude Code)`.
- Binary `bin/claude.exe`, sha256 `a186b99e4a9c88366cd49df2f7dad56c61fc306ef0140b19ee64b7c42a8d1348`.
- Harbor 0.24.0 `harbor/agents/installed/claude_code.py`.

Bash output limit (minified source in the binary):

    function _Xe(){return S(lt().bashOutputMaxChars)??t9n}
    function Zue(){let e=S(lt().bashOutputMaxChars);if(e!==void 0)return e;

The setting's own description in the binary: "How many characters of a successful Bash or PowerShell command's output Claude receives inline (default 30000; values clamp to 4000-128000). Output past this is saved to a file and Claude receives a short preview plus the path. When set, this also replaces BASH_MAX_OUTPUT_LENGTH, which on its own only sizes the read-back window."

Past the limit the model receives `Output too large (${size}). Full output saved to: ${filepath}` and `Preview (first ${gn(wxe)})` with `wxe=2000`.

Read tool limits:

    var n5r=25000 ... `File content (${e} tokens) exceeds maximum allowed tokens (${t}). Use offset and limit parameters ...`
    defaultFileReadingLimits ??= {maxSizeBytes: Xze, maxTokens: CLAUDE_CODE_FILE_READ_MAX_OUTPUT_TOKENS ?? n5r}
    Xze=262144

Harbor 0.24.0 sets neither `BASH_MAX_OUTPUT_LENGTH` nor `bashOutputMaxChars`; it only forwards `CLAUDE_CODE_MAX_OUTPUT_TOKENS` when set. The defaults apply to every trial.

Correction to D-0024: its context says single outputs of about 33,000 characters came back whole in the pilot. That figure double counts. Harbor's `_format_tool_result` writes the model-facing content and then appends `[stdout]` with the raw `toolUseResult.stdout`, so each trajectory observation holds the output twice. Splitting at `[stdout]`, the largest model-facing outputs in `results/pilot/2026-10-12-cc-claude-clean/` are 10,030, 11,031, 16,824, 13,702, 15,554 and 12,470 characters (one per trial, in the order a0 ledger, a0 port-conflict, a0 shipments, a1 ledger, a1 port-conflict, a1 shipments). None reached the 30,000 limit.

## Conclusion

On the pinned binary with Harbor's defaults:

- A `Bash` call returns at most 30,000 characters inline. Past that the model gets a 2,000 character preview and a file path.
- A `Read` call is refused above 25,000 tokens or 262,144 bytes unless the agent passes `offset` and `limit`.

The large Track N environments are sized so that the material each task needs is several times 30,000 characters, and no single file the agent must understand fits in one read.

Live observation of the persisted-output path on 2.1.289 needs a model call; it will come from the first D-0024 pilot trajectories (a `persisted-output` block in an observation). The same behavior was observed on Claude Code 2.1.296 in the maintainer session that ran this check, which is not the pinned version.
