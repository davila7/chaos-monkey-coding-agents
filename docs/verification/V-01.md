## Item

Claude Code mods: result field names in the build's types, loading under Harbor's headless invocation, plugin install and enable inside the container, behavior on subagent calls

## Why it matters

Core injector for the anchor config

## Versions under test

Claude Code 2.1.289 (the build whose API declaration file was read). The container load test will pin the version Harbor installs.

## Sources

- `claude-code.d.ts` written by the 2.1.289 engine for its plugin API (about 14,000 lines). Line references below are to that file.
- The plugin reference that ships with the same build (`reference.md`, section on running a plugin from disk).

## Evidence (documentation)

Hook signature: `on('tool.call', { tool }, ($, e, next) => ...)`. `e` carries the tool name in `e.tool`, the call id in `e.tool_use_id`, and the tool arguments as sibling fields (for `Bash`, `e.command`), not under an `input` key (lines 936 to 956). `tool` and `tool_use_id` are reserved; rewriting them is ignored.

Result shape, `ToolCallResult` (line 12139), three variants:

1. `{ deny: string }`: refuses the call; the model receives the text as an error result.
2. `{ result, context?, ref?, text?, isReadOnly? }`: an answered call. A hook's own `{ result }` is validated against the tool's output schema when it has one and is mapped for the model by the tool's own mapper. `text` is set by core on what `next(e)` resolves to (the result as the model reads it) and is absent on a hook's own result.
3. `{ isError: true, result, text?, ref?, context?, isReadOnly? }`: set by core when the tool threw, was interrupted, or answered an error.

Answering without `next` replaces the tool run: "Return `{ deny: reason }` to refuse or `{ result }` to answer yourself; a hook that returns while its `next` is pending aborts what runs beneath" (line 3842). Managed-settings hooks run first.

Subagents: `agentId` is set on events inside a subagent or teammate loop and absent on the main loop (type `AgentLoop`, line 196). A subagent's tool calls raise their own `tool.call` (line 12189), so one registration covers both loops.

Failure mode (line 3834): a hook that throws, overruns its budget, or returns a wrong shape is skipped; the hooks beneath and core run in its place. This is fail-open.

Time budget, `HookBudget` (line 4917): `ms: 10_000` per dispatch, counting only the hook's own time. "The clock stops while a `next(e)` call or any `$` call of the hook's is in flight (a `$.clock` wait excepted)." A `.catch` handler gets 1,000 ms.

Calling an external process: `$.process.run(argv, { cwd, env, stdin, timeoutMs })` resolves `{ exitCode, stdout, stderr }`, no shell, default timeout 30 s. The module itself runs without Node or a DOM, so the decision binary is reached through this call.

Headless loading (reference.md): `claude --plugin-dir <folder>` for one session, or `CLAUDE_CODE_PLUGIN_DIRS` (absolute paths, path-list separator) from the process environment or the `env` block of `~/.claude/settings.json`, never a project's settings. "A headless `claude -p` always loads fresh." A `-p` run in text mode reports a plugin whose module failed to load once on stderr; json and stream-json runs keep that line in the debug log only.

Plugin layout: `.claude-plugin/plugin.json`, `hooks/hooks.json` with `{ "modules": ["./register.ts"] }`, and `hooks/register.ts` exporting `register`.

## Design consequences for injector-claude-code

- The injector calls `tt-decide` through `$.process.run` with the generic stdin protocol. Because `$` calls stop the hook clock, decision latency does not consume the 10 s budget.
- `deny`, `err`, `ratelimit`, `falsefail`: return `{ deny: text }` without `next`. The model sees an error result. Whether a `deny` is distinguishable from a genuine tool error in the transcript is a conformance check.
- `empty`, `truncate`, `poison`, `drift`: call `next(e)` (or skip it for `empty`), then return `{ result }` with the transformed content. Because a hook's result is validated against the tool's output schema, each transform must produce a schema-valid record per built-in tool. This is a per-tool conformance item.
- `latency`: a `$.clock` wait counts against the 10 s budget, and catalog delays reach 20 s. Latency has zero weight in every profile (D-0005), so this does not block M1. If latency is enabled later, the delay must run inside `$.process.run` (a sleeping child) rather than a `$.clock` wait.
- Fail-open on throw means an injector crash silently produces a clean call. The injector must log `decision: "error"` before any step that can throw, and conformance must assert `crash_behavior: fail_open` in the capability file.
- `agent_id` in tt-events comes from `e.agentId`.

## Commands run

`claude plugin validate packages/injector-claude-code/dist/tt/cc` on 2.1.289 passes and reports `hooks: tool.call` and `calls: $.process.run`. A bundled single-file module was refused (the engine reported that `register` was not declared at the top of the file), so the plugin ships transpiled files (D-0014).

Container check without model calls (Harbor 0.24.0, `ubuntu:24.04`, job `probe5`): a subclass of `ChaosClaudeCode` uploaded the built layout to `/opt/tt` and ran, as the agent user:

- `claude --version`: `2.1.289 (Claude Code)`, installed by npm.
- `claude plugin validate /opt/tt/cc`: passed (`./register.js hooks: tool.call`, `calls: $.process.run`), exit 0.
- `tt-decide` with a forced `deny` config on a `Read` of `/app/x`: `{"apply":true,"type":"deny","phase":"pre","payload_id":"deny.eacces","text":"EACCES: permission denied"}`, and one `tt-event/2` record in `/logs/agent/tt/events.jsonl` synced to the host with `trial_id`, `attempt: 1` from `--ak attempt_index=1`, and `decision: "apply"`.

Observed: `/opt/tt` itself ends up mode 777 after upload, so an agent could rewrite the config or state. This does not change results under honest runs; the reward-hacking pass (D-0012) should check `/opt/tt` integrity, and the agent will tighten the mode in a later change.

Not yet observed: the hook firing inside a real `claude -p` session, which needs a model call.

## Remaining checks (need the pinned binary in a container)

1. `claude -p --plugin-dir /opt/tt/cc-plugin` loads the module under Harbor's invocation (stderr and debug log show no load failure). Needs one model call; part of the conformance probes.
2. A hook can return `{ isError: true, ... }` itself, or only `{ deny }` and `{ result }`. The types list `isError` as set by core.
3. `{ result }` schema validation per built-in tool (Read, Write, Edit, Bash, Grep, Glob) with transformed payloads.
4. `agentId` presence on a Task subagent's calls.
5. A `{ deny }` returned after `await next(e)` (used for `falsefail`, D-0014) reaches the model as an error result while the tool's side effect stands.

## Conclusion

Open. The API supports every Track N fault type needed for M1 except `latency` above 10 s through `$.clock`, which is out of scope under D-0005. Checks 1 to 4 run with the conformance probes once an Anthropic API key is available.
