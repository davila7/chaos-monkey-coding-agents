## Item

Runtime environment variables reaching compose services, or dataset variants per profile

## Why it matters

Proxy configuration

## Versions under test

- Harbor 0.24.0 (`harbor/environments/docker/docker.py`, `compose_env.py`), Docker Compose as installed in the cloud session.
- `datasets/cmca-s` compose files at this commit.

## Documentation and source read (2026-10-15)

- Harbor's Docker environment runs `docker compose` with `_compose_env_vars(include_os_env=True)`: the process environment of `harbor run` is the base, task and Harbor infra variables are merged on top (Harbor's win on collision). Compose then interpolates `${VAR}` in the task's `environment/docker-compose.yaml` from that environment.
- No Harbor CLI flag passes per-job variables to compose services directly; the process environment is the channel.

## Commands run (2026-10-15)

1. `python -m cmca_harbor.trials plan --track s --config oracle --profile clean --profile light --profile moderate --profile heavy ...`: one engine config directory per profile, one Harbor command per job, each prefixed with `env TT_CONFIG_DIR=<dir> TT_ATTEMPT=<a>`.
2. Those four oracle jobs plus one nop job, and one extra oracle job on `s-followups` with `TT_ATTEMPT=1`.

## Evidence

The compose file mounts `${TT_CONFIG_DIR:-./tickets/none}` at `/etc/tt` in the gateway and sets `TT_ATTEMPT: ${TT_ATTEMPT:-0}`. In the gateway logs (`results/task-validation/2026-10-15-cmca-s/summary.json`):

- clean job: every logged call has `exempt_reason` `not_applicable` and no fault applied, in all three tasks.
- light, moderate and heavy jobs: faults applied according to each profile (for example `s-duplicate-merge` heavy: deny 1, err 3, rate 2, trunc 4).
- the `TT_ATTEMPT=1` job: every event carries `"attempt": 1`; the other jobs carry `"attempt": 0`.

## Conclusion

Closed. Runtime variables of `harbor run` reach compose services through interpolation, so one dataset serves every profile and attempt; no per-profile dataset variants are needed. Two jobs with different `TT_CONFIG_DIR` values must not share one `harbor run` process.
