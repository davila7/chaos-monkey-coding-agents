## Item

Attempt index available to the agent environment

## Why it matters

Cross-config schedule parity: attempt `a` of every config must draw from the same fault schedule.

## Versions under test

Harbor 0.24.0 (`uv tool install harbor`, 2026-10-05).

## Commands run

```bash
uv tool install harbor
grep -n "n_attempts" .../site-packages/harbor/job_plan.py
```

## Evidence

`harbor/job_plan.py`, `JobPlan.build_trial_configs` (Harbor 0.24.0):

```python
for _ in range(config.n_attempts)
for task_config in task_configs
for agent_config in config.agents
```

The loop variable is discarded. `TrialConfig` has no attempt field, so the attempts of one task are identical trial configs. The agent receives nothing that tells attempt 0 apart from attempt 1.

## Conclusion

Closed. Harbor does not expose the attempt index. Use the SPEC 6.6 fallback: `cmca plan` emits one Harbor job per attempt index with `-k 1` and passes `--ak attempt_index=<a>`. Custom agents declare `attempt_index` in their `options_model` (see V-11 for how options are declared). The engine config written into the container carries it as `attempt`.
