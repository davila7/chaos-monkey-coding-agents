## Item

Codex hook install path through Harbor native config or `hooks.json`; passing `--dangerously-bypass-hook-trust`; single hook per event

## Why it matters

Hooks must load unattended

## Versions under test

- `@openai/codex` 0.163.0, in the V-02 image.
- Harbor 0.24.0 (`harbor.agents.installed.codex`), `ChaosCodex` (`python/cmca_harbor/src/cmca_harbor/codex.py`).

## Documentation read (2026-10-30)

- Codex config reference (https://learn.chatgpt.com/docs/config-file/config-reference): hooks load from `hooks.json` or from inline `[hooks]` tables, behind `features.hooks`.
- Harbor 0.24.0 `Codex`: takes a native config (`config` option) as the base, applies its own runtime inputs, and uploads the result to `$CODEX_HOME/config.toml` (`/tmp/codex-home`). Its `dangerously_bypass_hook_trust` option adds the flag to `codex exec`. Its default command already passes `--dangerously-bypass-approvals-and-sandbox`.

## Method and commands run

1. The four V-02 sessions (`docs/verification/V-02/all.sh`, output `V-02/2026-10-30-result.txt`). Each writes an inline `[[hooks.PreToolUse]]` and `[[hooks.PostToolUse]]` group with matcher `^(Bash|apply_patch)$` and one `command` hook (`timeout = 30`), the shape `ChaosCodex` writes. `deny-untrusted` is the `deny` session without `--dangerously-bypass-hook-trust`.
2. The V-28 conformance runs under Harbor (`docs/verification/V-28/conformance.sh`), where `ChaosCodex._build_effective_config` merges the hooks, `features.hooks`, the bridge provider and the model catalog over Harbor's config, and `build_cli_flags` adds the trust flag when the injector is active.

## Evidence

- With the flag, both events fire for `Bash` and `apply_patch` from one group each (V-02 result: 4 events in the `none` and `block` sessions, 2 `PreToolUse` in `deny`). Codex prints a warning item that the flag is on; the session continues.
- Without the flag (`deny-untrusted`): 0 events, both calls ran (`a.txt` is `hello world`), and neither stderr nor the `--json` stream mentions the hooks. An unattended run without the flag would run with no faults and no error, so `ChaosCodex` always adds the flag when the injector is active, and the conformance crash check would not catch its absence; the injector's events log does (no `decide` events for an exposed call).
- Under Harbor, every conformance trial logged its injector decisions in `agent/tt/events.jsonl` (V-28).

## Conclusion

Install path: inline `[hooks]` in Harbor's `config.toml`, `features.hooks = true`, `--dangerously-bypass-hook-trust`, one command hook per event on `^(Bash|apply_patch)$` (`ChaosCodex`). No `hooks.json` file is needed. MCP tool calls are not matched; Track S faults go through the MCP fault proxy (D-0044 item 4).
