(b) Tools. Main agent tools seen in hook payloads: `bash` (`tool_input` `{command, description, workdir}`), `write_file` (`{path, content}`), `edit_file` (`{path, find, replace}`), `read_file` (`{path}`). Reminder children call `submit_reminder_decision`. Proposed SPEC 6 mapping: `bash` shell, `write_file` fs.write, `edit_file` fs.edit, `read_file` fs.read.

(c) Hooks. `.muse/hooks.json` in the Claude Code shape (`{"hooks":{"<Event>":[{"matcher":"*","hooks":[{"type":"command","command":"..."}]}]}}`) loads with no warning; an unknown event or invalid JSON gives `Hooks: 0 runnable · 1 warning`. Payload fields: `hook_event_name`, `cwd`, `model`, `model_provider`, `permission_mode` (`bypassPermissions` under `--yolo`), `session_id`, `turn_id`, `tool_name`, `tool_input`, `tool_use_id`, `transcript_path` (null), plus `tool_response` (PostToolUse) or `error`, `duration_ms`, `is_interrupt` (PostToolUseFailure). Hook environment: `HOME MUSE_SESSION_ID MUSE_THREAD_ID PATH PWD TRACEPARENT`. `MUSE_SESSION_ID` equals the payload `session_id` for main agent calls only, so the injector can leave reminder children alone (run `d`).
- A `bash` call that exits non-zero fires `PostToolUseFailure`, not `PostToolUse` (runs `b`, `d`).
- `PreToolUse` deny, by exit 2 with the reason on stderr or by `{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"deny","permissionDecisionReason":R}}`: the model receives `tool blocked by hook: R` (run `c`, as quoted back by the model).
- `PostToolUse` replacement, by `{"decision":"block","reason":X}` or exit 2 with X on stderr: the model receives X verbatim in place of the result, for `bash` (run `c`) and for `write_file`, `read_file`, `edit_file` (run `d`). `hookSpecificOutput.updatedToolOutput` is ignored (run `c`).
- `PostToolUseFailure` cannot replace: with exit 2 and stderr, `decision: block`, or `updatedToolOutput`, the model still receives the original failed result, and the hook text arrives as separate context next to it (run `e`). So post-phase faults (`empty`, `trunc`, `poison`) cannot change what the model sees for a shell command that exits non-zero.
- What the model sees for a successful `bash` call is a JSON object `{chunk_id, exit_code, terminal_status, output, original_output_bytes, original_output_tokens, truncated}` (failed calls add `terminal_reason`); a replacement must rebuild it.

(e) Egress, run `f`: the container sat on a Docker network with no route out (`--internal`) and `HTTPS_PROXY` pointing at `egress-proxy.py`, which logs each `CONNECT`. Muse honoured the proxy; the only host was `api.meta.ai:443` (5 connections, `f/connect.log`). Connections that ignore the proxy would fail on that network and are not logged.
