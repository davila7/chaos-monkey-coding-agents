## Item

Codex `PostToolUse` with `decision: "block"`: how the replacement text is framed to the model

## Why it matters

Decides whether Codex output faults enter any parity set (D-0044 item 3: hook-feedback framing would leave them out).

## Versions under test

- `@openai/codex` 0.163.0 from npm (`codex --version`: `codex-cli 0.163.0`), in `V-02/Dockerfile` on `node:22-bookworm-slim` (`mirror.gcr.io/library/node@sha256:4b150b48b4116e2a22f2c39cc27025fbf4f153e2078fd3b14d159fdb5c7279da`).
- Model metadata from `configs/codex-claude.catalog.json` (V-28), so `apply_patch` is a native tool.

## Documentation read (2026-10-30)

- Codex config reference (https://learn.chatgpt.com/docs/config-file/config-reference): `features.hooks`, inline `[hooks]` tables or `hooks.json`, `PreToolUse` and `PostToolUse` command hooks with `matcher` and `timeout`. The answer shapes used here (`decision: "block"` with `reason`, `hookSpecificOutput.permissionDecision: "deny"`) follow the Claude Code hooks schema, which Codex's hooks mirror; what Codex does with them is taken from the observed requests below, not from the documentation.

## Method

`V-02/stub.py` stands in for the Responses API and plays `V-02/script.json`: an `exec_command` call that prints `hello` and exits 3, then an `apply_patch` call that changes `a.txt`, then a final message. `V-02/hook.sh` is registered for both events on `^(Bash|apply_patch)$`, records each event, and with `MODE=block` answers every `PostToolUse` with `{"decision":"block","reason":"REPLACED"}`, with `MODE=deny` every `PreToolUse` with a deny whose reason is `REFUSED`. The model-facing bytes are the `function_call_output` and `custom_tool_call_output` items in the last request Codex sends to the stub.

## Commands run

`IMAGE=<V-02/Dockerfile image> OUT=<dir> sh docs/verification/V-02/all.sh`: four containers with `--network none`, one session each (`MODE` none, block, deny, and deny without the trust flag for V-03), then `V-02/show.py`. Output: `V-02/2026-10-30-result.txt`.

## Evidence

From `V-02/2026-10-30-result.txt`:

- No hook output: Codex sends the command result as `Chunk ID: 42c8e2\nWall time: 0.0000 seconds\nProcess exited with code 3\nOriginal token count: 2\nOutput:\nhello\n` and the patch result as `Exit code: 0\nWall time: 0 seconds\nOutput:\nSuccess. Updated the following files:\nM a.txt\n`.
- `MODE=block`: both outputs are the bare string `REPLACED`, in the same `function_call_output` and `custom_tool_call_output` items. No hook name, no prefix, no frame. The command and the patch still ran (`a.txt` is `hello world`).
- `MODE=deny`: `Command blocked by PreToolUse hook: REFUSED. Command: printf 'hello\n'; exit 3`, and the same with the patch text for `apply_patch`. Neither ran (`a.txt` is `hello`), and no `PostToolUse` fired.
- Event fields: `exec_command` arrives as `tool_name` `Bash` with `tool_input` `{"command": ...}`; `apply_patch` as `apply_patch` with the patch in `tool_input.command`. `tool_use_id` is the model's call id. `tool_response` for `Bash` is the raw output (`hello\n`) with no exit code; for `apply_patch` it is the whole model-facing text, frame included.
- The rollout file named by `transcript_path` already holds the `item_completed` record of the call when `PostToolUse` runs: for `call_sh`, `exit_code` 3 and `duration` `{secs: 0, nanos: 8478}`.
- `Original token count` is the UTF-8 byte count divided by 4, rounded up: 6 bytes (`hello\n`) give 2.

## Conclusion

The block text reaches the model as the tool's output, so output faults stay in Codex's parity set. Because the frame is dropped, `packages/injector-codex` rebuilds it: for a command, the header with the exit code and duration read from the rollout file, the token count of the new output, and a chunk id derived from the call id (Codex's is random); for a patch, the original `Exit code` and `Wall time` lines, or exit code 1 for `falsefail`. A command whose output is above Codex's own truncation limit is passed unchanged, since the injector would have to reproduce Codex's truncation header. Pre-phase faults (`deny`, `err`) carry Codex's wording, which names the hook: attribution is visible, as for fxh (V-27).
