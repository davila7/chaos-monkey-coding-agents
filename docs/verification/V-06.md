## Item

OpenCode v2: `execute.before` and `execute.after` fire on success and failure; MCP calls pass through hooks; Harbor installs v2

## Why it matters

v1 has reported hook bugs

## Versions under test

- Harbor 0.24.0, `harbor/agents/installed/opencode.py`
- npm `opencode-ai`: `latest` = 1.18.34, `beta` = 0.0.0-beta-202608110357 (dist-tags read 2026-10-05)
- npm `@opencode-ai/plugin`: `latest` = 1.18.34, `beta` = 0.0.0-beta-19271

## Commands run

```bash
npm view opencode-ai dist-tags --json
npm pack @opencode-ai/plugin@latest && grep -n "tool.execute" package/dist/index.d.ts
npm pack @opencode-ai/plugin@beta && grep -n "execute.before\|execute.after\|hook" package/dist/promise/tool.d.ts
```

## Evidence

1. Harbor installs `npm i -g opencode-ai@<version>` and defaults to `@latest` when no version is given (`opencode.py`, `install`).
2. `opencode-ai@latest` is 1.18.34. Its plugin package exposes the v1 hooks `tool.execute.before` and `tool.execute.after` (`dist/index.d.ts` lines 235 and 249), which SPEC 9.3 excludes because of reported v1 hook bugs.
3. The v2 tool hooks `execute.before` and `execute.after` under `hook` (`dist/promise/tool.d.ts` lines 29, 37, 55) exist only in `0.0.0-beta-*` and `0.0.0-next-*` snapshot builds. No semver v2 release is published.

## Conclusion

Open. SPEC 9.3 says to support v2 only, on a pinned v2 release, and none exists on npm as of 2026-10-05. The options are:
(a) pin an exact beta snapshot and treat each snapshot bump as a harness version bump that reruns conformance,
(b) run OpenCode on the v1 hooks with conformance as the gate, against SPEC 9.3, or
(c) defer `opencode-claude` until a v2 release ships.
Not yet tested: whether hooks fire on failure and whether MCP calls pass through them. Both need a running binary and a model.
