## Evidence (documentation and types)

| Item | 1.0.3 behavior |
|---|---|
| Block | `tool_call` returns `{ block: true, reason }` (`ToolCallEventResult`). |
| Input mutation | `event.input` is mutable in place; no re-validation after mutation. Return values only control blocking. |
| Result replacement | `tool_result` returns a partial patch `{ content?, details?, structuredContent?, isError? }`; handlers chain in load order. Setting `isError: true` makes the model see an error. |
| `structuredContent` | "Handlers that redact `content` should also replace this; replacing `content` alone drops it." The built-in `bash` tool declares an output schema with `output`, `truncated`, `full_output_path`. |
| Parallel calls | Sibling calls from one assistant message are preflighted (`tool_call`) sequentially, then executed concurrently; `tool_result` may interleave in completion order. Correlation is by `toolCallId`. |
| Nested calls | Calls made by other tools (codemode) pass through the same handlers with `parentToolCallId` and ids `<parent>/<n>`. |
| Failure mode | "A `tool_call` handler failure blocks the tool as a fail-safe." This is fail-closed, the opposite of Claude Code. |
| Node built-ins | Available to extensions (`node:child_process` used for `tt-decide`). |
| Loading | `--extension <path>`, repeatable; Harbor's Pi agent already uses it for its own extensions. |

Built-in tools: `read`, `write`, `edit`, `bash`, `grep`, `find`, `ls`, `powershell`. The default active set in print mode is `read`, `bash`, `edit`, `write` (observed in the system message of the probe run below), so `fs.search` and `fs.list` reach Pi agents only through `bash` unless `--tools` enables `grep`, `find` and `ls`.

## Commands run

- Unit tests in `packages/injector-pi` run both handlers against the real `tt-decide` bundle.

## Design consequences for injector-pi

- Pre-phase types return `{ block: true, reason }`. Post-phase decisions are kept by `toolCallId` and applied in `tool_result`.
- `falsefail` returns `isError: true` with the catalog text after the tool ran. `empty`, `trunc`, `poison` replace the text content and, when present, `structuredContent.output`.
- Because a throwing `tool_call` handler blocks the tool, every handler path catches and passes through; an injector failure must never produce an unscheduled block.
- `inarg` (native-only) is possible through input mutation but has weight 0 in every profile (D-0005), so it is not implemented in M1.
