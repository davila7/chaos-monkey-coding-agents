## Item

D-0037 item 2 lets a `[[poison]]` declaration name `tool = "shell"` and a `source` file. The engine decides eligibility from the command text without changing it, and the post-phase transform replaces, in the command output, the source lines the variant changes. D-0037 item 5 asked whether each Track N harness passes the rewritten output to the model unchanged and whether it adds text of its own.

## Why it matters

Every Track N agent in the pilots read files through the shell, so a poison declaration on `fs.read` was never eligible (D-0036 item 6). A harness that drops or wraps the rewritten shell output needs a `parity_gaps` entry (D-0017).

## Versions under test

- Claude Code 2.1.289, Pi 1.0.3, OpenCode 1.18.35, the pinned builds of `capabilities/`.
- Harbor 0.24.0, conformance runner `python -m cmca_harbor.conformance`, injector builds from this branch (`packages/injector-*/dist/tt`).
- Catalog v1 with `poison.variant` applying to `shell`.

## Method

The `probe-shell` conformance task gains a shell poison declaration on `/app/probe/notes.txt`. Its variant changes one line, `Last line: cobalt-5521`, to `Last line: moved, see ticket pmt-4e81c2`. The probe instruction runs `cat /app/probe/notes.txt; touch /app/probe/shell.done` and asks for the last printed line. The runner's poison check passes a trial when the token reaches the model in the observation of the shell call.

Commands (one per attempt `a` in 0, 1, 2 and harness), from `conformance plan` restricted to `-i probe-shell`:

    uv run harbor run -p datasets/conformance -a cmca_harbor:ChaosClaudeCode -m claude-sonnet-5-5 -k 1 -o jobs/v23/claude-code-new --job-name conf-claude-code-poison-a<a> -y -i probe-shell --ak attempt_index=<a> --ak tt_config_dir=<plan>/configs/poison --ak tt_build_dir=packages/injector-claude-code/dist/tt --ak version=2.1.289 --ak extra_ca_cert=/root/.ccr/ca-bundle.crt --agent-setup-timeout-multiplier 3 -n 1
    env -u ANTHROPIC_BASE_URL uv run harbor run -p <copy of datasets/conformance with the sandbox proxy CA> -a cmca_harbor:ChaosPi -m anthropic/claude-sonnet-5-5 ... --ak version=1.0.3
    uv run harbor run -p <copy of datasets/conformance with the sandbox proxy CA> -a cmca_harbor:ChaosOpenCode -m anthropic/claude-sonnet-5-5 ... --ak version=1.18.35

The Pi and OpenCode installs fetch Node through Harbor before the agent starts, so the CA must be in the image; the first Pi and OpenCode run, without it, failed at install (`curl: (60)`) in all six trials, made no model call, and is not counted. The capability files were then rebuilt with `conformance report` over the committed evidence of the earlier conformance runs plus these trials, with the same `--gap` arguments as before.

In each trajectory the observation is the file with only the last line replaced, and the agent quotes the replaced line. Model cost of the nine trials: $0.086 (Harbor `agent_result.cost_usd`).

Evidence: `results/conformance/<harness>@<version>/conf-<harness>-poison-a<a>/probe-shell__*/`; capability files `capabilities/*.json`, cell `faults.poison.classes.shell`.

## Not covered here

- Targeted false failures (D-0037 item 3) apply on Track S only, through the MCP fault gateway, whose `falsefail` delivery the Track S probes checked (D-0029 item 3, `results/conformance-s/`); the per-trial selection is covered by `packages/fault-engine/test/targeted.test.ts`.
- Shell output that prints the source through a program that changes its lines is not rewritten by design (D-0037 item 2); the analysis counts those events as not delivered.
