## Documentation read (2026-10-15)

- Harbor 0.24.0 `fx` agent runs `fx ask --yolo --json -- <instruction>` and tees stdout to `/logs/agent/fx.json`. It does not override `populate_context_post_run` and collects no trajectory, token counts or cost.
- https://github.com/vercel-labs/fx: with `--json` the final answer is in `final_output`; sessions are saved under `~/.fx/sessions/`. The session file format and the full JSON schema are not documented.
- https://fx.sh/docs/lib/api: libfx emits `tool_start` and `tool_end` turn events (observation only).

## Versions under test

- fx 0.0.13, Harbor 0.24.0.
- Model `openai/gpt-5.4-nano` on the AI Gateway free tier.

## Commands run

1. `fx ask --yolo --json --model openai/gpt-5.4-nano -- "Use the tickets MCP server: call get_ticket for id 211, then write the ticket title to title.txt in the current directory using a shell command."` against the gateway and `tickets` service, with `HOME` pointing at a fresh directory.
2. `session_to_atif` (`python/cmca_harbor/src/cmca_harbor/fx.py`) on the resulting `~/.fx/sessions/<id>/`, then `harbor.utils.trajectory_validator.validate_trajectory` on the output (`python/cmca_harbor/tests/test_fx.py`, with the captured session committed under `tests/data/fx-session-0.0.13`, workspace path replaced by `/app`).

## Evidence

- The run exited 0 and made 6 tool calls: `mcp_select_tool` (failed: `Dynamic MCP tool not found or not allowed: get_ticket`), `mcp_features` twice, `capability_search`, `mcp_tickets_get_ticket`, `shell`. Usage 49,052 input and 533 output tokens, `total_cost` $0.0054 in `usage-v2.json` (free-tier credits).
- `sessions/<id>/` holds `events.jsonl` (one `{"schema_version":3,"seq":n,"timestamp_ms":..,"event":{<kind>:{...}}}` per line, kinds `user`, `assistant`, `tool_call`, `tool_result`, `turn_completed`), `tool-results/<artifact_ref>` with each full tool output, and `usage-v2.json` with session totals.
- `tool_call` carries `call_id`, `tool_name` and `arguments_json`; `tool_result` carries `call_id`, `status`, a `preview` and `artifact_ref`. All 21 events in this session have the same `timestamp_ms`, so per-step timestamps are not usable.
- fx shows MCP tools to the model as `mcp_<server>_<tool>` and wraps each MCP result in `{"server":"tickets","tool":"mcp_tickets_get_ticket","result":{...}}`; the `isError` flag and text of the MCP result are inside `result` unchanged.
- The converted trajectory validates (`validate_trajectory` returns true), has one ATIF tool call per fx tool call, one observation per tool result with the full output from `tool-results/`, and final metrics from `usage-v2.json`.

## Conclusion

Closed. `ChaosFx` (Harbor's `fx` agent plus collection) copies `~/.fx/sessions/<session_id>/` to `/logs/agent/fx-session/` after each run and writes `/logs/agent/trajectory.json` (ATIF-v1.5) and the context token counts and cost from it. Step timestamps are left empty because fx does not record them per event. The gateway's injection log stays the source of truth for which calls were faulted; the trajectory shows what the model saw.
