## Why it matters

Harbor 0.24.0 cannot run Pi 1.0.3 with MCP servers at all (`harbor/agents/installed/pi.py` raises `ValueError` outside `>=0.84.1,<0.86.0`). With the default `codemode` exposure every MCP result would pass through a script the model writes, so delivery and attribution would not compare with `cc-claude` and `fx-claude`.

## Documentation read (2026-10-18, `docs/mcp.md` in the 1.0.3 package)

- Servers come from `mcp.json` in the agent directory (`~/.pi/agent`, or `$PI_CODING_AGENT_DIR`); a `url` selects streamable HTTP. Tools are named `mcp__<server>__<tool>`.
- `direct` exposure declares a tool "to the model like a built-in tool". Codemode activates when a server with `codemode` exposure connects; `"autoEnableCodemode": false` beside `mcpServers` prevents it. The first prompt waits up to 10 seconds for servers with direct tools.
- "Text results over 20 KB reach the model with their middle removed around a `…N chars truncated…` marker."
- "A result with `isError` ... is reported as an error for direct calls."
- HTTP network errors and 408, 429 and 5xx statuses are retried twice; for resources, "Tool calls are not retried because the server may already have performed them."
- An installed extension that registers `/mcp`, such as `pi-mcp-adapter`, replaces the built-in support. `ChaosPi` loads no such extension.

## Evidence

- **Sibling pin.** `ChaosPi.install_command()` writes a `package.json` that overrides every `@earendil-works` package the harness depends on, directly or through a sibling, to the harness version, installs with `--ignore-scripts`, and links `pi` into the nvm Node's `bin`. Resolved: `chord`, `pi-agent-core`, `pi-ai`, `pi-codemode`, `pi-coding-agent`, `pi-mcp`, `pi-telemetry` and `pi-tui`, all 1.0.3; `pi --version` printed `1.0.3`. `pi-telemetry` is reached only through `pi-ai` (`^1.0.3`); a first override list built from the direct dependencies alone left it at 1.3.0, which is why the script walks the tree. Both Harbor trials installed through the same method; Harbor recorded agent version `1.0.3`.
- **Connection.** `pi mcp list`: `tickets: connected, 5 tools (direct, global)`, listing `search_tickets, get_ticket, create_ticket, add_comment, update_status`; exit 0.
- **Direct exposure under Harbor.** In both trials each request declared `read`, `bash`, `edit`, `write` and `mcp__tickets__search_tickets`, `mcp__tickets__get_ticket`, `mcp__tickets__create_ticket`, `mcp__tickets__add_comment`, `mcp__tickets__update_status`; no codemode tool. On the built-in provider path (`check.sh`) the list also carries `__pi_deferred_placeholder__` with `defer_loading: true` and the description "Reserved placeholder. Never available. Never call this."
- **Tool name.** The trajectory records the call as `mcp__tickets__get_ticket` with `{"id": 501}`; the gateway logged `get_ticket`. `cmca_analysis.ingest` already strips this prefix (Claude Code form).
- **Clean result.** The ticket JSON reached the next model request as a `tool_result` with `is_error: false`, and the trajectory observation holds the same text. One gateway event, `decision: pass`.
- **Failed result.** Under `err` the gateway applied `err.timeout.30s`. The next model request carried a `tool_result` with `is_error: true` and content exactly `Error: ETIMEDOUT: operation timed out after 30000ms`; the trajectory observation is the same string, with no text added by Pi. One gateway event for the one call: Pi did not repeat the call itself.
- **Reasoning setting (for V-08).** With `--thinking medium` on the built-in provider, Pi 1.0.3 sent `thinking: {"type": "adaptive", "display": "summarized", "block_binding": {...}}`, a top-level `output_config: {"effort": "high"}`, and, as the last message, a `system` message with empty content and `output_config: {"effort": "medium"}`. The code path is `pi-ai/dist/api/anthropic-messages.js`: for models whose catalog entry has `compat.supportsMidConvoEffort` (`claude-sonnet-5-5` has it) the top-level effort is fixed to `high` and the session's level goes into mid-conversation messages. Claude Code 2.1.289 sends `display: "omitted"` and a top-level `effort: "medium"` (V-08). Which effort the API applies when both are present needs an API call and is not verified.
- Under Harbor with a base URL set, Pi uses Harbor's custom provider (`harbor-endpoint`, `model_api` required) and sent budget thinking (`type: enabled`, `budget_tokens: 8192`) instead. That path is not the one the probes use.
- The two trials made no model API call; Harbor reported `cost_usd: null` and reward 1 (the probe verifier always writes 1).
