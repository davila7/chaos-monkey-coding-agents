## Item

Harbor custom agents subclassing installed agents, `populate_context_post_run`, `/logs/agent` sync, `--ak` and `--ae` behavior

## Why it matters

Integration foundation

## Versions under test

- Harbor 0.24.0 (`harbor --version`), Docker environment.
- Claude Code 2.1.289, installed in the container by `npm install -g @anthropic-ai/claude-code`.
- Task image: `ubuntu:24.04`.

## Probe

A subclass of Harbor's installed `ClaudeCode` agent, loaded with `-a module:Class`. It makes no model call. Its `run` writes one JSON line to `/logs/agent/tt/events.jsonl` containing the value of an environment variable passed with `--ae`, the output of `claude --version`, and an agent kwarg passed with `--ak`, then solves a one-line task (`echo hello > /app/out.txt`). `populate_context_post_run` reads that file from `self.logs_dir` and copies it into `context.metadata`.

```python
class ProbeOptions(ClaudeCodeOptions):
    attempt_index: int | None = Field(default=None)

class ProbeClaudeCode(ClaudeCode):
    options_model = ProbeOptions
    async def install(self, environment): ...   # npm install, see Findings 5
    async def run(self, instruction, environment, context): ...
    def populate_context_post_run(self, context):
        p = self.logs_dir / "tt" / "events.jsonl"
        context.metadata = {"tt_events_found": p.exists(), "tt_events": p.read_text() if p.exists() else None}
```

## Commands run

```
harbor run -p hello -a probe_agents.cc:ProbeClaudeCode --ak attempt_index=2 --ae TT_PROBE=xyz -o jobs --job-name probe4 -q
```

## Evidence

Trial directory `jobs/probe4/hello__Zu8axaZ/`:

- `agent/tt/events.jsonl` was synced from the container:
  `{"probe_env": "xyz", "claude": "2.1.289 (Claude Code)", "attempt_index": 2 }`
- `result.json` `agent_result.metadata`:
  `{"tt_events_found": true, "tt_events": "{\"probe_env\": \"xyz\", \"claude\": \"2.1.289 (Claude Code)\", \"attempt_index\": 2 }\n"}`
- `config.json` agent block: `{"name": "probe_agents.cc:ProbeClaudeCode", "kwargs": {"attempt_index": 2}, "env": {"TT_PROBE": "xyz"}}`
- `verifier/reward.txt`: `1`. Job mean 1.0, no exceptions.

## Findings

1. A subclass of an installed agent loads with `-a module:Class` when the module is on `PYTHONPATH`.
2. `--ak key=value` is rejected with "Unknown option" unless the key is declared in a pydantic `options_model` that extends the parent's options class. Declared keys are typed and read through `self.options`.
3. `--ae KEY=VALUE` reaches commands run through `exec_as_agent`.
4. Files written under `/logs/agent/` inside the container appear under `<trial>/agent/` on the host before `populate_context_post_run` runs, and `context.metadata` set there is persisted in `result.json`.
5. Harbor 0.24.0 installs Claude Code on non-Alpine images with `curl https://downloads.claude.ai/.../bootstrap.sh`. In this development sandbox that host is denied by the egress policy (probe3 failed with `curl: (22) ... 403`, classified as `NetworkConnectionError`). Overriding `install` to use npm works. The CMCA agent will install a pinned version through npm so the installed binary does not depend on the bootstrap host and the version is explicit.
6. Reported from the owner's Mac (2026-10-10, not committed evidence): with Colima only `$HOME` is mounted into the VM, so the Harbor jobs directory must be under `$HOME` or `/logs` never syncs back.
7. The sandbox also needs its proxy CA inside task images. This is a property of the development environment only and is not added to benchmark task images.

## Conclusion

Closed. The CMCA Harbor agents subclass the installed agents, take `attempt_index` (V-12) and other settings as declared options, pass injector settings through environment variables, and collect tt-events from `/logs/agent/tt/` in `populate_context_post_run`.
